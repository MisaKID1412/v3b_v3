# v3b_v3 pipeline contract

The public entry point is `run_from_images.sh`. Every dataset follows the same
eight stages.

1. **Frontend reconstruction** — DA3 depth/pose inference, generalized
   RoomFormer polygon recovery, SAM3 reject masks, robust room refit, strict
   image-to-atlas projection, and LaMa completion.
2. **Unified proposals** — four appearance components create deliberately fine
   spatial proposals; persistent horizontal bands are retained as structural
   proposals. These proposals are not final material identities.
3. **Material identity and trace-back** — geometrically incoherent proposal
   groups are removed. MatSeg compares original-view descriptors, with a
   contact-frame corroboration only for two non-structural singletons.
   Untraceable structural support may rejoin an already surviving material only
   when both MatSeg frames agree. A native-scale guard rejects undersampled
   structural outliers. Each surviving material is then regenerated by the
   maximum-projection-mass, weight-ordered original v3b trace-back algorithm.
4. **CHORD PBR** — unchanged CHORD runs on every 512x512 rectified source-image
   input with one inference configuration and produces BaseColor, normal,
   roughness, and metallic.
5. **Material layout** — traced exemplars are composed, and the accepted v1
   backend infers arbitrary-N material territories using strict observations.
   A validated ordered architectural-layer solution wins a near energy tie
   (within 0.01) over unconstrained nearest-region fill; the rule depends on
   measured support and axis consistency, not on room or face names.
6. **Whole-territory PBR** — only evidence-supported horizontal or vertical
   architectural boundaries are regularized. The backend selects smooth,
   stochastic, directional-spectral, structured, or nonstationary-spectral
   whole fields from measured exemplar statistics. It does not use a fixed tile
   grid or patch cut-and-paste.
7. **Unity project** — the room OBJ/MTL and aligned four-channel PBR maps are
   exported with packed metallic/smoothness and an Editor importer.
8. **Unity package** — the project directory is archived as an importable Unity
   package and linked to an end-to-end SHA-256 provenance manifest.

Room names, face names, room shape, and material counts are excluded from the
selection rules. Known-camera metadata and cached DA3 results change only how
camera/geometry evidence is supplied; they do not select another material path.
